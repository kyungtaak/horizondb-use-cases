05 · SQL AGGREGATION

판매 지표의 SQL 집계

현재 Repository의 KPI 계산 구조 발췌 · 바인딩값 사용
SELECT
  count(*) FILTER (
    WHERE paid_at < %s) AS paid,
  coalesce(sum(amount) FILTER (
    WHERE paid_at < %s), 0) AS gross,
  count(*) FILTER (
    WHERE paid_at < %s
      AND cancelled_at < %s) AS cancelled
FROM commerce.orders
WHERE run_id = %s;

REFERENCE 03 · IMPLEMENTATION EXCERPTS

SQL과 pipeline 정의 발췌

집계와 AI 변환은 같은 DB를 쓰지만, 서로 다른 처리 경로입니다.

주문 시각을 고정 구간으로 묶기 · 현재 SQL의 핵심 구조

SELECT
  date_bin(
    b.step, o.paid_at,
    '1970-01-01'::timestamptz
  ) AS minute,
  count(*) AS orders
FROM commerce.orders o
CROSS JOIN bounds b
WHERE o.run_id = %(run)s
  AND o.paid_at >= b.start_at
  AND o.paid_at < b.as_of
GROUP BY 1

step은 10초 또는 60초. 빈 구간은 별도 bucket과 결합해 0건으로 표시.

pipeline 구성 발췌 · 이름·모델·prompt·충돌 정책 등은 생략

source => ai.table_source(
  table_name => 'analysis_batches',
  schema_name => 'commerce',
  incremental_column => 'updated_at'),
steps => ARRAY[ai.generate(
  input => 'content',
  system_prompt => %s,
  max_tokens => 8192, model => %s)],
trigger => 'on_change',
sink => ai.table_sink(
  table_name => 'batch_results',
  schema_name => 'commerce', ...)

출력은 generated_text. 5초·10건 묶음 생성 자체는 백엔드에서 수행.

timeline.py · setup.py / 설명용 발췌이며 그대로 실행하는 완성 SQL은 아님14 / 16
